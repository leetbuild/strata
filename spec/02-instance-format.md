# 02 — Instance format

Strata's files are MO2's files. Pillar 1: MO2/Fluorine and Strata alternate on one instance with no loss.
**Verify every detail below against the MO2 source** (`modorganizer/src/`: `profile.cpp`, `modlist*.cpp`,
`modinfo*.cpp`, `settings*.cpp`, `instancemanager.cpp`, `executableslist.cpp`, `pluginlist.cpp`; game plugins
for `plugins.txt`). This page is the checklist, not the authority.

## Rules for every file
- Round trip: reading and writing a file without changes gives the same bytes (line endings, BOM, key order,
  comments, unknown sections and keys). A property test covers this per file type.
- Writes are atomic (temp file + rename) and only happen when content changed.
- Qt `QSettings` ini quirks must be reproduced exactly: `@ByteArray(...)`, `@Variant(...)`, `@Size(w h)`,
  escaped `\\` and `%U` sequences, array sections (`size=`, `1\key=`), keys with `/` stored as `\`.
  Write a dedicated `qsettings` ini module with tests taken from real files (a real instance's
  `ModOrganizer.ini` is a good corpus).
- Paths stored by MO2 on Windows (`C:\...`, `Z:\...`) and by Fluorine on Linux both occur. Normalise on read,
  write back in the form found.

## Instance folder
```
<instance>/
  ModOrganizer.ini        [General] gameName, gamePath, selected_profile, version...; [Settings] base_directory,
                          mod/download/cache/profiles/overwrite dirs (%BASE_DIR%), style, ...;
                          [customExecutables] array; [Plugins] per-plugin settings; [fluorine] Fluorine keys
                          (prefix, proton, steam_drm, ...) — read them for the Proton setup, keep them
  mods/<Name>/            files + meta.ini
  profiles/<Profile>/     modlist.txt, plugins.txt, loadorder.txt, archives.txt (LE), settings.ini,
                          local inis (Skyrim.ini, SkyrimPrefs.ini, SkyrimCustom.ini), saves/ (local saves)
  overwrite/              files written by programs at run time
  downloads/              archives + <archive>.meta
  webcache/, logs/, crashDumps/, stylesheets/, backups/
  Game Root/, Prefix/     (a common Linux layout, not MO2's: paths come from the ini)
  strata/                 Strata's own files (whiteouts.txt, journals, scan cache). MO2 and Fluorine ignore it
```
Portable vs global instances, `portable.txt`, `%BASE_DIR%`: see MO2's `instancemanager.cpp`.

## modlist.txt
- First line comment `# This file was automatically generated by Mod Organizer.`
- One line per mod: `+Name` enabled, `-Name` disabled, `*Name` unmanaged/foreign (DLC, game files).
- **Top line = highest priority** (the reverse of the left pane's priority numbers). Check the source.
- Separators are mods named `<Name>_separator`.
- Overwrite is not listed.

## meta.ini (per mod)
`[General]` gameName, modid, version, newestVersion, category (comma list, trailing comma), installationFile,
repository, url, hasCustomURL, nexusFileStatus, comments, notes, color (separators), endorsed, tracked,
lastNexusQuery, nexusLastModified, converted, validated; `[installedFiles]` array (modid, fileid);
`[Plugins]` per-plugin data, including **`Sub-Separator\nest`** (Leet) on separators. Preserve everything.

## plugins.txt / loadorder.txt
SSE: `plugins.txt` lists plugins with `*` for enabled, in load order, without the base masters; `loadorder.txt`
lists every plugin in order. LE: no `*`, only enabled plugins. Both live in the profile and are copied to the
prefix's `AppData/Local/<Game>/` at launch (MO2 does this through the VFS; Strata overlays those prefix folders, see
`spec/03-vfs.md`). Locked plugins: `lockedorder.txt`.

## downloads/<archive>.meta
`[General]` gameName, modID, fileID, url, name, description, modName, version, newestVersion, fileTime,
fileCategory, category, repository, userData, installed, uninstalled, paused, removed. Preserve.

## Sizes to expect
Small instances have a few dozen mods; large curated lists have well over 1,000 mod folders, hundreds of
GB and dozens of nested separators. Formats and indexes must scale to that.
